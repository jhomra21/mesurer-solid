# Responsive inspector

Responsive opens with one iPhone 15 preview at 393 × 852 CSS pixels. Add up to six previews from the preset and breakpoint list. Each preview has a Size selector, independent width and height controls, removable/reorderable headers, and same-origin live iframes. The Size selector changes only that preview; choosing a page breakpoint changes its width and preserves its height. Width and height are rounded and clamped to 240–3840 CSS pixels. Duplicate sizes create separate previews with distinct identities, and Add is disabled at six previews. Preview order changes visually without moving iframe nodes, so resizing and reordering do not reload pages.

Fit scales every preview by the same factor, using the largest viewport and the available stage space. Manual zoom levels are available from the control bar. Preview list, zoom, and per-preview Guides remain in memory for this page while Responsive closes and reopens. They reset when the page key (origin, pathname, or query) changes, and are never persisted to storage.

With Guides active, drag in a preview to create a guide, select and drag it to reposition, hold Shift to multi-select, hold Alt to show distance evidence, press Delete to remove only selected preview guides, or drag a guide beyond the preview edge to remove it. Guides snap to elements in that preview's own document and are stored in its CSS-pixel coordinates. Root-page guides are hidden and cannot be edited while the stage is open; they remain unchanged and reappear when it closes. Zoom does not change guide coordinates. Leaving Guides mode keeps the evidence visible but disables its interaction layer.

Rulers remain page-scoped. Activating Rulers closes Responsive so page rulers are shown on the original page rather than projected into previews. When Layout Guides is enabled, its shared page settings are projected into each preview at that preview's width; this does not create separate Layout Guide settings or change page-scoped Layout Guide state.

While the stage is open, its same-origin preview is the active inspection source. Select hover, click and marquee selection, measurements, X-ray, and Typography inspect elements in the preview, including accessible nested same-origin frames. Hold Shift while clicking to add or remove an element, or while dragging a marquee to add its enclosed elements. Evidence is projected into Mesurer's root overlay at the scaled preview position. The original page and the stage chrome are not inspection sources while the stage is open. Closing the stage clears preview selection and hover state.

The Inspect info card follows the **Settings > Select > Info card mode** preference. Click mode shows a selected element's card; Hover mode also shows a pass-through selector preview when no element is selected. A selected card remains interactive in Responsive, including copy buttons and the CSS-details expansion. With **Layout details** on, it shows the same computed CSS rows and expansion control as the root-page card, and expanded content scrolls within the visible stage. Its dimensions and computed CSS come from the preview element's source document, while its placement uses the root-projected measurement. When the stage has a gutter of at least 168 CSS pixels, the selected card docks beside the device preview, so the rest of the preview stays hoverable. In a narrower stage, the card is placed directly below the selected element when it fits, or above when the space below is insufficient. It stays horizontally clamped to the visible stage and avoids covering the selection when either vertical side fits. If neither side fits, the card stays visible below the target, clamped to the stage; this can cover part of a very tall selection. It repositions on window resize, stage scroll, and preview scroll, and remains clipped to the visible stage. In Responsive, hover and selection outline bounds are snapped in their existing overlay coordinate space to the owning window's device-pixel grid. Each visible edge uses an equal, whole-device-pixel thickness (rounded DPR device pixels, for example 2 pixels at DPR 2). Labels and measurement values retain unsnapped geometry. The card and its tooltips stay in Mesurer's protected root overlay; no inspector UI is mounted into a preview document. Typography, Edit/direct text editing, Alt-distance presentation, active drags, and capture UI suppress the competing Inspect card.

While Responsive is open, drag the selected card by its header row to move it out of the way. The header shows a grab cursor, then a grabbing cursor after the drag threshold; small clicks still activate the header's copy controls. The card stays at its manually chosen position as preview selection changes, is clamped inside the visible stage, and is re-clamped when the window or stage changes. Closing Responsive clears the manual position, so reopening returns to automatic placement. The main-page Inspect card is not draggable.

Context can annotate preview selections. Each element target adds `viewport: { url, width, height, previewId }` and a `domPath` for nested same-origin frames and open shadow roots, preserving the selector, fingerprint, immutable baseline, and existing root viewport CSS-pixel geometry. Replies and resolve status belong to that saved parent annotation and persist with it. URL identity excludes the fragment but includes the pathname and query. Markers, panels, and the composer stay in the root overlay; Mesurer does not mount another Context UI in the preview document.

Only preview notes appear while Responsive is open; only root-page notes appear while it is closed. Resolution requires the exact URL, width, and height. The original preview id wins when still present; a recreated preview may rebind only when exactly one viewport matches and the stored selector/fingerprint resolves conservatively. Missing or ambiguous targets stay unresolved. Resizing a preview away from the saved size hides its notes until the exact viewport returns. No note migrates to a same-width/different-height viewport or another route.

The Context-owned **Notes** toolbar list searches both original notes and replies and filters Open, Resolved, or All (default Open). Selecting a row is the only automatic reveal action. It opens or closes Responsive as needed, reuses an exact URL/width/height preview when identity is unambiguous, and creates a missing saved size. If all six slots are occupied, it replaces the last preview. The original preview id remains preferred and missing, ambiguous, different-URL, invalid-size, or refused targets remain saved with an explanatory list status. It does not navigate the page or a preview to another URL. Revealing waits for the loaded frame and target rebind, scrolls nested source frames and the owning preview row, and preserves root page scroll. The list remains open alongside the note card. Escape, closing a surface, route changes, and deleting a note cancel pending reveal; context/review reads never reveal or scroll.

Preview notes require selected elements within one preview; empty regions and selections spanning different previews cannot create a note.

Removing a preview immediately releases its Context document watchers and hides its markers/panels, but keeps the saved records. Closing Responsive releases preview documents and transient selection/composer state while retaining records. Reopening reloads the retained sizes at the current root URL and rebinds matching notes. Notes retain Context's page-keyed same-tab session persistence, independently of Responsive's in-memory settings; after a page-key change, only that page's notes are loaded, and returning to the old page restores its records. Reload resets preview settings, not saved notes. Deleting a preview note through its panel affects only that annotation; Delete in a preview never deletes root-page notes.

`annotations()` exposes the saved descriptor, and `context()` exposes it per target and as `previewViewport` for preview evidence. `capturePlan()` includes `previewViewport` with root-projected capture geometry. `coordinateSpace` remains `"viewport-css-px"` in the root viewport. `window.__MESURER__` keeps its existing methods: selector-based `inspect()`/`select()` remain root-scoped, while selection/annotation Context reads the actual human-selected preview target.

The page must allow itself to load in same-origin iframes. Cross-origin frames, `X-Frame-Options`, CSP `frame-ancestors`, and frame-busting code can prevent that. Mesurer shows a refusal message when it cannot access the loaded document; inspection then finds nothing in that refused preview.

Previews reload the live page in same-origin iframes and run its JavaScript. Requests, analytics, and other page side effects repeat for every preview that is added. Up to six live documents can consume substantial memory and network resources. The iframe sandbox suppresses some browser actions, but it is not a security boundary. Use Responsive only on pages whose scripts you are willing to run again.

The page behind the stage is scroll-locked while Responsive is open. Wheel input over the empty stage moves only the preview row; wheel input inside a frame scrolls that preview and hands horizontal movement to the row when possible. Closing Responsive restores the page's prior inline `overflow-x` and `overflow-y` values and priorities. A page-key change while the stage is open closes it and resets the in-memory preview state.

Entering Responsive exits Edit and clears the current selection. Edit and Rulers close the stage because they operate on the original page. Color Picker, Screenshot, and Recording remain available above the stage: color sampling includes visible previews, and capture selection can select and capture preview pixels. Cancelling a capture returns to inspection without closing or recreating the previews. B is ignored by editable controls, including open Shadow DOM inputs in the preview. Turning off global shortcuts disables B without disabling Escape.

Responsive is a built-in feature and is on by default. Turn it off in **Settings > Plugins**, or omit it with `excludeBuiltins: ["responsive"]`. Press **B** to open or close it; Escape and a click on the empty stage also close it.

## Chromium extension limits

The extension uses activeTab rather than broad host permissions. Built extension asset checks cover manifest permissions, preview keyboard behavior, and page-level reinjection only. Real toolbar-action activation, activeTab authorization, and automatic extension recovery remain manually verified; reinjecting scripts in a normal page context does not test those browser-managed paths.
